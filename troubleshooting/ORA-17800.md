# ORA-17800: Got minus one from a read call

Remote client reaching the database through NAT. Telnet to the port works, the connection test passes, opening the database fails.

## Fix

Connect by SID instead of service name.

```
hr@orcl.example.dom    fails
hr@orcl                works
```

A static `SID_LIST` entry is served by the listener directly, so no address is returned to the client. Check it is static, not dynamic:

```
lsnrctl status
```

`UNKNOWN` against the SID is static. `READY` is dynamic and will regress on a listener restart.

## Why

By service name the listener hands back the registered local listener address and the client reconnects there. Behind NAT that address is private and unreachable.

```
lsnrctl services
show parameter listener
srvctl config scan
```

The permanent fix is mapping the NAT to every address the listener publishes, not leaving clients on a SID. SID connections are deprecated and do not work against a PDB.
