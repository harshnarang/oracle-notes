# ORA-04030: out of process memory when trying to allocate bytes

**Applies to:** 11g to 23ai

## Cause

A server process could not get private memory from the OS. This is PGA, not the shared pool, so the session dies and the instance carries on.

Either the machine was out of memory, or the process hit its own limit first. The second one fails while `free` still shows memory, because the ulimit came from whatever started the listener.

The text in brackets names the consumer. `PLS` is PL/SQL, usually a `BULK COLLECT` with no `LIMIT`. `kxs` is cursor state. The third is a sort or hash sized off a bad row estimate.

## Check

The trace file named in the alert log has the memory breakdown for the process that died. Read it first.

Who is holding PGA now:

```sql
SELECT   s.inst_id, s.sid, s.serial#, s.username, s.program, s.sql_id,
         ROUND(p.pga_alloc_mem/1024/1024) AS alloc_mb
FROM     gv$process p
JOIN     gv$session s ON s.paddr = p.addr AND s.inst_id = p.inst_id
ORDER    BY p.pga_alloc_mem DESC
FETCH    FIRST 20 ROWS ONLY;
```

Then break that process down. `SQL` is work area memory and Oracle can shrink it, `PL/SQL` and `Other` it cannot:

```sql
SELECT   inst_id, pid, category,
         ROUND(allocated/1024/1024)     AS alloc_mb,
         ROUND(max_allocated/1024/1024) AS max_mb
FROM     gv$process_memory
WHERE    pid = &pid
ORDER    BY allocated DESC;
```

If the trace points at a limit rather than exhaustion, read the limits the process ran under:

```
cat /proc/<spid>/limits
```

## Fix

Kill the session if it is still growing:

```sql
ALTER SYSTEM KILL SESSION '&sid,&serial,@&inst_id' IMMEDIATE;
```

Caution: rollback can take as long as the work did, and the memory comes back only when it finishes.

OS limit: raise it for the oracle account, then restart the listener and the instance. A running process keeps the old limit.

Work area: check the plan for that `sql_id` before changing parameters. Raising the target only buys room.

```sql
-- illustrative, size to the instance and to free memory
ALTER SYSTEM SET pga_aggregate_target = 16G SCOPE=BOTH SID='*';
```

PL/SQL: no parameter helps. Add the `LIMIT` and process in batches.

## Prevent

- `LIMIT` on every `BULK COLLECT`.
- ulimits set for the oracle account and inherited by the listener.
- Alert on `maximum PGA allocated` in `gv$pgastat` against physical memory.
- Cap parallelism on ad hoc reports. At DOP 32 a 200 MB work area is 6 GB.
