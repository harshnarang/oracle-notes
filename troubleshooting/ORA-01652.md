# ORA-01652: unable to extend temp segment

**Applies to:** 11g - 23ai

## Cause

A sort, hash join or index build required more space in the tablespace than was available. The statement fails and its temp space is released.

The tablespace named in the error is not always TEMP. Index rebuilds and `CREATE TABLE AS SELECT` raise the same error against a permanent tablespace.

On RAC the temporary tablespace is shared but extents are cached per instance, so usage has to be read across all instances.

## Check

Temp usage by session, all instances:

```sql
SELECT   u.inst_id,
         s.sid,
         s.serial#,
         s.username,
         s.sql_id,
         ROUND(u.blocks * p.value / 1024 / 1024) AS mb_used
FROM     gv$sort_usage u
JOIN     gv$session s ON s.saddr = u.session_addr
                     AND s.inst_id = u.inst_id
CROSS    JOIN (SELECT value FROM gv$parameter
               WHERE  name = 'db_block_size' AND inst_id = 1) p
ORDER BY mb_used DESC
FETCH FIRST 20 ROWS ONLY;
```

Reading `V$SORT_USAGE` on a single node returns only that node's sessions and will show nothing when the session responsible is on another instance.

Free space in the temporary tablespace:

```sql
SELECT tablespace_name,
       ROUND(free_space/1024/1024)      AS free_mb,
       ROUND(tablespace_size/1024/1024) AS total_mb
FROM   dba_temp_free_space;
```

Statement text for the session consuming the space:

```sql
SELECT DISTINCT sql_text
FROM   gv$sql
WHERE  sql_id = '&sql_id';
```

Execution plan for that statement:

```sql
SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR('&sql_id', NULL, 'ALLSTATS LAST'));
```

`MERGE JOIN CARTESIAN`, hash joins over large row counts, and sorts on unfiltered result sets are the usual sources.

## Fix

Terminate the session consuming the space:

```sql
ALTER SYSTEM KILL SESSION '&sid,&serial,@&inst_id' IMMEDIATE;
```

Caution: this rolls back the session's uncommitted work. Temp space is released immediately.

Add a tempfile where the tablespace is genuinely undersized. Size is illustrative; on a production instance temp is often tens to hundreds of GB, so extend in increments suited to the workload:

```sql
ALTER TABLESPACE temp
  ADD TEMPFILE '+DATA' SIZE 4G AUTOEXTEND ON NEXT 512M MAXSIZE 32G;
```

On RAC the tempfile must be on shared storage, otherwise the other instances cannot use it. `MAXSIZE` should always be set; unbounded autoextend allows a single statement to fill the diskgroup.

Refresh statistics where row estimates are wrong:

```sql
EXEC DBMS_STATS.GATHER_TABLE_STATS('&owner', '&table_name');
```

Check `PGA_AGGREGATE_TARGET`. Sorts that would fit in memory spill to disk when it is set too low:

```sql
SELECT inst_id, name, value/1024/1024 AS mb
FROM   gv$parameter
WHERE  name IN ('pga_aggregate_target', 'pga_aggregate_limit')
ORDER  BY inst_id, name;
```

## Prevent

- Gather statistics after bulk loads and keep the automatic statistics job enabled.
- Give reporting workloads a separate temporary tablespace.
- On RAC, run reporting through a dedicated service on a dedicated instance.
- Limit session resource usage with a profile:

```sql
ALTER PROFILE report_users LIMIT LOGICAL_READS_PER_CALL 5000000;
```

- Alert on temp usage at 80 percent rather than on failure.
- Review execution plans for new reports before they are scheduled.

## Version notes

- 11g onwards `DBA_TEMP_FREE_SPACE` is available. Earlier versions require `V$TEMP_SPACE_HEADER`.
- 12c onwards each PDB can have its own temporary tablespace. Confirm which tablespace the failing session uses before resizing.
