# ORA-01555: snapshot too old

**Applies to:** 11g - 23ai

## Cause

A query needs a read-consistent image of a block as it looked when the query started. The undo required to rebuild that image has already been overwritten by other transactions. The query fails. The instance is unaffected.

On RAC each instance has its own undo tablespace. The relevant one is the tablespace belonging to the instance the query ran on.

## Check

Undo tablespace in use by each instance:

```sql
SELECT inst_id, value AS undo_tablespace
FROM   gv$parameter
WHERE  name = 'undo_tablespace'
ORDER  BY inst_id;
```

Longest query seen against retention actually held:

```sql
SELECT   inst_id,
         MAX(maxquerylen)         AS longest_query_secs,
         MAX(tuned_undoretention) AS retention_secs
FROM     gv$undostat
GROUP BY inst_id
ORDER BY inst_id;
```

`longest_query_secs` greater than `retention_secs` on any instance confirms the cause.

Size of the undo tablespaces:

```sql
SELECT   tablespace_name,
         ROUND(SUM(bytes)/1024/1024) AS mb,
         MAX(autoextensible)         AS autoextend
FROM     dba_data_files
WHERE    tablespace_name IN (SELECT UPPER(value) FROM gv$parameter
                             WHERE  name = 'undo_tablespace')
GROUP BY tablespace_name
ORDER BY tablespace_name;
```

Retention guarantee setting:

```sql
SELECT tablespace_name, retention
FROM   dba_tablespaces
WHERE  contents = 'UNDO';
```

`NOGUARANTEE` allows undo to be overwritten before `undo_retention` is reached when space is needed.

## Fix

Raise retention above the longest query runtime:

```sql
ALTER SYSTEM SET undo_retention = 10800 SCOPE=BOTH SID='*';
```

`SID='*'` applies the change to all instances. `undo_retention` is a target only and is ignored when the undo tablespace is too small to honour it, so size the tablespace first.

Add space to the undo tablespace of the affected instance:

```sql
ALTER TABLESPACE undotbs1
  ADD DATAFILE '+DATA' SIZE 4G AUTOEXTEND ON NEXT 512M MAXSIZE 32G;
```

Enable retention guarantee once undo is sized correctly, on each undo tablespace:

```sql
ALTER TABLESPACE undotbs1 RETENTION GUARANTEE;
```

Caution: with `GUARANTEE` set, new DML fails when undo is full rather than undo being overwritten.

## Prevent

- Do not commit inside a fetch loop. Committing while a cursor is still open allows the undo that cursor depends on to be recycled.
- Set `undo_retention` to at least the runtime of the longest batch job and size undo to support it.
- Run long reports on a dedicated service pinned to one instance, so the undo requirement is predictable.
- Run reporting against a physical standby where one is available.
- Alert when `gv$undostat.maxquerylen` approaches `tuned_undoretention`.

## Version notes

- 10g onwards: automatic undo management is the default.
- 12.2 onwards in a CDB, undo may be shared at CDB level or local to each PDB. Check `UNDO_MODE` before sizing.
